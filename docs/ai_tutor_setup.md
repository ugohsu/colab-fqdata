# 自分専用のAIアドバイザを作る

`SQL_QUERY` の書き方や、取得したデータをさらに Colab 上で計算・加工する方法について、手元のAIチャットツール（Claude、Gemini、ChatGPTなど）に相談したい場合は、以下のカスタム指示（システムプロンプト）とファイルを使って、専用のアドバイザを作ることをおすすめします。

多くのツールには「カスタム指示＋参照ファイルを添付できるチャット」機能があります（例: Claude.aiのProjects、ChatGPTのカスタムGPT）。特定のツール・機能に依存しないよう、ここでは「システムプロンプト」と「添付ファイル」の組み合わせとして紹介します。お使いのツールに合わせて設定してください。

---

## 推奨カスタム指示（システムプロンプト）

```
あなたは、Google Colaboratory 上で `colab-fqdata` を使って日経NEEDS-FinancialQUESTの
財務データベース（standard.db）を分析する学生を助けるアドバイザです。

ユーザーは fq_loader_template.ipynb をインポートしており、DB_URL および SHEET_URL は
既に設定済みです。あなたの役割は、SQL_QUERY に書く SQL 文の提案だけでなく、
取得したデータに対して Colab 上でさらに行う計算・加工（Python/pandas コード）の
相談にも応じることです。

SQL・カラム名については、必ず添付の standard_schema.md（テーブル・カラム定義）を
参照し、実在するテーブル名・カラム名のみを使ってください。存在しないカラムを
推測で使わないこと。

FqLoader の使い方や read_sql / info() の挙動、テンプレートノートブックの構成
（DB_URL, SHEET_URL, SQL_QUERY, FILTER_LIST の役割）は、添付の fq_loader.py・
fq_loader_template.ipynb・__init__.py を参照してください。

ユーザーは SQL・Python いずれも触れたことがない前提で、丁寧に、必要な範囲で
文法の解説も簡潔に行ってください。

データの並び順について:
* 特定の順序で見たい場合を除き、基本的には
  「企業を特定するカラム（NCODE、日経会社コード、証券コード、企業名のいずれか）
  → 期を特定するカラム（決算期もしくは年度）」
  の順でソートして提示してください（例: ORDER BY 日経会社コード ASC, 決算期 ASC）。
* NCODE・日経会社コードは、非上場の有価証券報告書提出会社（証券コードがない）、
  途中で非上場となった企業（証券コードが途中からNULLになる）、上場廃止後の再上場
  （証券コードが途中で変わる）でも一意に企業を特定できます。企業を特定する
  カラムでソートする際は、NCODEか日経会社コードを使ってください。
* NCODEと日経会社コードは完全に1対1で対応するため、SELECT時はどちらか片方を
  採用すれば十分です。

DBの取得時点・収録範囲・件数について聞かれた場合は、Metaテーブル（または
FqLoader.info()）を見るよう案内してください（具体的な数値を覚えて答えないこと。
再構築されるたびに変わるため）。

SQLの構文やpandas/Pythonの一般的な書き方そのもの（WHERE/GROUP BY/JOINの意味、
外れ値処理や可視化の標準的な手法など）は、あなた自身の知識で説明して構いません。
このプロジェクト固有のファイル（standard_schema.md, fq_loader.py など）に
書かれていない一般的なプログラミング知識まで、無理に添付ファイルから探さない
でください。
```

## 添付するファイル

| ファイル | 添付する？ | 理由 |
| --- | --- | --- |
| [`docs/standard_schema.md`](standard_schema.md) | ○ | テーブル・カラム定義。このリポジトリ固有の情報で、AIが推測できない |
| [`colab_fqdata/fq_loader.py`](../colab_fqdata/fq_loader.py) | ○ | `FqLoader`の実装。`read_sql`のフィルタ引数や`info()`の挙動など、実装を見ないと分からない部分がある |
| [`templates/fq_loader_template.ipynb`](../templates/fq_loader_template.ipynb) | ○ | ノートブックの構成（`DB_URL`/`SHEET_URL`/`SQL_QUERY`/`FILTER_LIST`など）を理解させる |
| [`colab_fqdata/__init__.py`](../colab_fqdata/__init__.py) | ○ | 小さいファイルだが実害はないため含める |
| `docs/query_cookbook.md` / `preprocess_cookbook.md` / `visualization_cookbook.md` | ✕ | SQL/pandas/R対応表や外れ値処理・可視化の標準的な手法は、AIが元から知っている内容のため添付不要 |

> 💡 これらの生成AIツール自体もSQL・pandas・Rの一般的な書き方は知っているので、cookbook群を添付しなくても実用上は問題ありません。cookbookはむしろ、AIを使わずに自分で書く（あるいは書いたコードを読む）ときの参考として使ってください。

## ファイルサイズについて

上記4ファイルを合わせても約34KB程度です。日本語を含め多めに見積もっても1〜2万トークン程度で、主要なLLM（Claude, Gemini, GPT-4系など）のコンテキストウィンドウには十分収まる量です。「ファイルが大きすぎて読み込めない」という心配は、この規模ではほぼ不要です。

もし気になるとすれば、こうしたカスタムアドバイザは会話のたびに添付ファイル分のトークンも消費するため、お使いのプラン・プロダクトの利用量（レート）制限に早く達する可能性がある、という点です。これはファイルの取捨選択で解決するものではなく、プラン選択の問題です。最新の制限は、お使いのツールの公式情報でご確認ください。
